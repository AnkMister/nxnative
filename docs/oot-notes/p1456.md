## Numerical correction to upstream

Upstream lets a standalone HMMA use slot zero even while an earlier HMMA chain
still holds that slot. A synthetic standalone call inserted between a chain's
producer and consumer caused 8,089 outputs over tolerance, maximum absolute
error 8.874. An actual translator fixture independently confirmed slot zero was
assigned to both operations. This is a correctness failure, not a performance
tradeoff.

The port reserves slot 7 for temporary/non-chain results; slots 0–6 serve live
chains. When seven chains are occupied, later chains materialize register
results instead. This retains the existing 16-matrix allocation. GPU and
translator regressions cover an interleaved standalone call, and a separate
translator test covers eight overlapping chains with overflow. The fixed GPU
probe has zero outputs over tolerance, maximum error 0.01385.

The numerical tests retain upstream's CPU reference and thresholds:

- Single HMMA: `0.01 + abs(reference) * 0.004`, 256 SIMD-groups; measured
  maximum absolute error 0.008845, zero outputs over tolerance.
- Four calls, including two-call accumulations, A reuse, direct plain/transposed
  A and zero C: `0.02 + abs(reference) * 0.008`, 64 SIMD-groups; measured maximum
  absolute error 0.01385, zero outputs over tolerance.
- The interleaved standalone-call fixture uses the same two-call reference and
  threshold, with the same 0.01385 maximum and zero over tolerance.

These are synthetic M4 Max checks. Movie speed and image parity are unverified.
The PR author's 26.65 to 18.85 ms result is not a local measurement.

## #1334 and review 4b merge contract

The user chose a #1456-only port on main. This branch does not add the fork's
#1334 tensor library or its Apple10 host selector. `DMSH_HMMA_CHAIN` is separate
from `DMSH_HMMA_TENSOR` (build the optional `_bt`) and `DM_NVN_HMMA_TENSOR`
(select it on Apple10). It does not require an Apple10 GPU.

When combining this branch with #1334, do not apply its old
`HMMA_SIMDGROUP = HMMA_BODY[...]` slice or `hmma_tensor_msl` matcher to the new
retained-matrix body. Those expect the ordinary helper layout and materialized
C/D registers. Safe integration choices are:

1. Keep #1334 on an ordinary-ABI translation/build variant, independent of the
   chain variant, and select complete matching libraries; or
2. Implement and numerically verify a new tensor lowering for the flagged ABI,
   including materialization at every dependent call. Disabling only the MSL
   slot-return branch is insufficient if its input ABI/dataflow is mismatched.

Until one is implemented, do not advertise combined `_bt` support. Preserve
review 4b's repair: `fetch_finish` compiles `<key>_bf.metallib` whenever `mac`
is in TARGETS. Neither HMMA option may gate ordinary readable-tile output. A
regression checks all four chain/tensor option combinations against that exact
production expression. Off-mode helper tests also prove the tensor option
alone does not enable the chain rewrite.
